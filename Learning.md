## 2. The Goal

- **I want to fully understand the code in `freee-payroll/` and be able to read any part of it.**
- If I can answer every test question correctly by the end, I should be able to read any part of the repo.

## 3. The Scope

- Ruby
- Ruby on Rails
- TypeScript
- React
- (Plus anything else the repo uses that I need in order to read it: RSpec tests, Sorbet types, SQL/database basics, OpenAPI, Git, the command line, and so on.)

## 4. Who I am (so lessons are written for me)

- I am a **beginner / junior developer**.
- I **don't understand the codebase at all** yet.
- Assume I **don't know any software engineering terms**. Explain every term the first time it appears.

## 5. What each lesson must teach

For **each language/framework** (Ruby, Rails, TypeScript, React, ...):

- the basics
- concepts
- the meaning of terms (assume I know none)
- clear examples
- anything relevant that I will actually use in `freee-payroll/`

## 6. Lesson format rules

- Each lesson should take **about one hour** so it is easy to digest.
- Add **practice parts** when needed.
- Lessons should use **real examples from `freee-payroll/`** and match the practices used there.
  (The lessons were reviewed against the repo's actual code and its rules in `CLAUDE.md`, `app/CLAUDE.md`, `front/CLAUDE.md`, `spec/CLAUDE.md`, and `docs/knowledge/`.)

## 7. Test format rules

Mix these question types:

- **Multiple choice**: for terminology questions
- **Build the code**: for code-related questions
- **Fill in the blanks / fill in the missing code**
- **Answer in a sentence**

## 8. Answer key rules

- Make an answer key for **every** test (`AnswersN.md` matches `TestN.md`).
- Explain *why* an answer is right, not just what it is.

## 9. The spirit of the whole thing

- "Basically it's like creating an entire **crash course** for me on the `freee-payroll/` repo."
- Add anything else that is relevant or helpful.
- I'm open to suggestions and other ways to learn.

## 10. Suggested study method (added by Claude)

1. Read the lesson with the real repo open in my editor beside it. When a lesson gives a file path, **open that file** and find the code.
2. Do the practice parts **by typing** (don't copy-paste). Ruby practice can run in `irb`; TypeScript practice can run in the [TypeScript Playground](https://www.typescriptlang.org/play).
3. Take the test **without looking** at the lesson. Then check `AnswersN.md`.
4. Anything I got wrong: re-read that section and write it in "My Notes" below.
5. Tick the box in `LessonPlan.md`.
6. After every few lessons, do the "Code Reading Drill" at the end of the lesson: open a random file in the repo and try to explain each line out loud.
